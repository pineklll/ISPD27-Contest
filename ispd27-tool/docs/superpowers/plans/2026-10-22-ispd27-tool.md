# ISPD27 A-lite Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a focused, legally changed MCMM contestant submission, improve it with sizing/buffering and safe batching, then add the staged pin-swap extension without building a generic ECO framework.

**Architecture:** OpenROAD is the only mutable design authority; Python makes decisions from immutable Snapshot observations. One client owns initialization, ECO dispatch, checkpoints, actual-state checks and clean output reload. A small harness invokes the official evaluator/scorer; production does not duplicate routed signoff or official score arithmetic.

**Tech Stack:** Linux/POSIX, Python 3.9+ standard library, Bash, Tcl, `unittest`, OpenROAD `8443f6ff398e3c4e06cb65a05a0abf22734ad345`, development/evaluator Kepler Formal, supported image `udxs/ispd27:v1-fixed`.

**Spec:** [ISPD27 Submission Tool — A-lite Design](../specs/2026-10-22-ispd27-tool-design.md). This plan replaces the earlier twelve-task full-A plan. The spec owns architectural/policy decisions; this document pins implementation interfaces and evidence. Both are revised drafts for review, not authorization to start product implementation.

## Global Constraints

- Entry point: `run.sh <input_dir> <platform_dir> <output_dir> <top_module>`; exactly four positional arguments and arbitrary cwd.
- Required output filenames come from `OUTPUT_DEF` and `OUTPUT_VERILOG`; never reconstruct them from the top module or directory basename. The output directory exists and is empty on entry.
- Tool runtime and total-flow runtime are each limited to `18000` seconds; setup must finish within two hours. Offline production uses Python 3.9+ standard library, with no pip/venv/ML dependency.
- Resources: 1 NVIDIA A100 (40 GB), 16 physical cores/threads, 64 GB RAM, 200 GB disk. `NUM_CORES`: positive integer, default 8, capped at 16.
- Defaults: tool limit `12600 s`, finalization reserve `1800 s`, external-evaluation margin `5400 s`; request deadlines never exceed remaining phase budget. These are margins, not a hidden-benchmark runtime guarantee.
- OpenROAD owns all mutations. Python may compare transient immutable audit data but must not implement a mutable netlist, projected-ECO graph or inverse-move executor.
- Snapshot/Move are the only public versioned JSON contract families. Use `schemas/snapshot_v1.json` and `schemas/move_v1.json`; no standalone DesignView/TimingReport/RPC schemas.
- Preserve all fixed physical/clock/protected/PG data and actual source/parity invariants. Loaded Liberty functions validate choices; only the vendored authoritative catalog authorizes changed/inserted masters.
- Complete MCMM/hold/ERC checks start with the first real loop. Bounded path detail may not truncate global acceptance metrics. All observations use explicit ns/fF/um/um²/W units.
- Local hold/ERC policies and setup objective are exactly spec §7.3, anchored to immutable B0. Official absolute hold penalties/certification are separate development concerns.
- No runtime evaluator/reference/harness access. All run/evaluation directories and score files are fresh. Never modify official evaluator, benchmarks or platform to make results pass.
- An unchanged baseline is calibration only. No changed locally validated checkpoint means failure, never baseline-as-success. Tool-side placement estimates are not routed/signoff certification.
- Do not create an algorithm registry/contract, generic backend interface, full Python design/library model, separate emitter/rollback/report packages or independent official scoring clone.

## Review Focus

1. Special-character paths/identifiers must survive shell/Tcl dispatch as data, not executable text; Task 1 includes a real initialization/export exercise.
2. Same-named clocks with distinct periods, virtual clocks and multiple scenario identities must keep independent constraints; Task 1 validates actual scene contexts and one-time unit conversion.
3. Partial mutation, legalization failure and process death must restore actual graph/timing plus version/generation, with no detached workers; Task 2 tests the transition and exercises real recovery.
4. A baseline outside official hold tolerances must permit baseline-preserving gains without cumulative degradation; Task 3 pins numerical policy and no-output-on-failure behavior.
5. Old Python observations must never become design authority: after an accept/reload use fresh engine observations, and final export disagreement must not publish stale success; Tasks 2–3 prove those cases.

### Concrete data and callable boundaries

- `Config` in `config.py` holds absolute input/platform/output/MCMM paths, top module, resolved OpenROAD executable, profile and numeric limits. `parse_config(argv: Sequence[str], env: Mapping[str, str]) -> Config` consumes the four contest arguments. All required output paths come from env; conflicting supplied identities fail closed.
- Initial `ISPD27_PROFILE` is `sizing`; add `buffering`/`combined` when buffering exists, and `pin-swap` in Task 7. This is a small explicit conditional in the optimizer, not runtime algorithm discovery. Final default becomes `combined` in Task 5.
- `Snapshot` in `model/timing.py`: schema `ispd27.snapshot/1`, `design_version`, `generation`, `state`, optional `candidate_id`, `fidelity=placement`, immutable scenario metrics, bounded paths/target/neighborhood/library-choice observations, total area/cell count and artifact identities. Required scalar scene fields include `setup_tns_ns`, `setup_wns_ns`, `hold_tns_ns`, `hold_wns_ns`, `slew_sum_ns`, `cap_sum_ff`, `fanout_sum`, `dynamic_power_w`, `leakage_power_w`. Keep exact `mode`, `constraint_mode`, corner, clock/coverage metadata and paths separate per scenario.
- Compact `Target`, `MasterChoice`, path and net observation records live alongside Snapshot, not a general design/catalog module. Target choice facts include function/interface, approval group, cap/area/geometry and protection reasons. Net observations identify the actual driver and all sinks for a selected cut. No mutating methods or live engine handles.
- `Endpoint` in `model/moves.py` is `(instance, pin)` with exact DB names; empty instance denotes top-level. `Candidate` has schema `ispd27.move/1`, id, strategy, base generation/version, ordered moves and optional predicted gain. JSON readers reject unknown schemas/ops, missing preconditions and nonfinite quantities; no JSON Schema library is required.
- Move records are `Resize(inst, old_master, master)`, `InsertRepeater(net, driver, sinks, master, name, new_net, x_um, y_um)`, `RemoveRepeater(inst, input_net, output_net)` and Task 7's `SwapPins(inst, mapping)`. Insert uses an exact net cut; remove merges all actual output sinks upstream; swap mapping is the full destination-to-original-source input permutation. Compound moves may reference earlier created names.
- `OpenRoadClient(config: Config, work_dir: Path)` in `openroad/client.py` provides blocking `start() -> Snapshot`, `checkpoint(tag: str) -> Checkpoint`, `apply(candidate: Candidate) -> Snapshot`, `accept(trial: Snapshot) -> Snapshot`, `restore(checkpoint: Checkpoint) -> Snapshot`, `validate_export(checkpoint: Checkpoint, stage_dir: Path) -> Snapshot`, `close() -> None`. `Checkpoint` is private client metadata: immutable baseline/current artifact identities and the accepted token, not another public schema.
- Client `apply` uses actual state for all pre/postchecks and returns trial-state data at the candidate's base accepted version. `accept` advances accepted version once and produces fresh accepted observations; `restore` returns remeasured actual state. A rebuilt search process increments generation and invalidates old proposals. A separate export verifier does not become a new search process or feed proposals back into search.
- `load_approved(path: Path) -> Mapping[str, int]`, `validate_candidate(snapshot: Snapshot, candidate: Candidate) -> None`, and `check_actual(baseline_dir: Path, current_dir: Path, approved: Mapping[str, int]) -> dict` live in `openroad/checks.py`. Invalid checks raise `ValueError`; successful actual-state checks return `passed=True`, `changed_from_baseline` and transformation counts. The client performs additional live expected-master/connection checks before mutation. Private audit exports include all actual graph/fixed data needed for global checks, even though proposal Snapshots are bounded.
- `feasible(trial: Snapshot, baseline: Snapshot, config: Config) -> bool` and `objective(snapshot: Snapshot, baseline: Snapshot, config: Config) -> float` live in `scoring.py`. `should_accept(trial: Snapshot, current: Snapshot, baseline: Snapshot, config: Config) -> bool` combines actual local legality, feasibility and the strict objective comparison. All comparisons require matching fidelity/scenario identities.
- `propose_sizing(snapshot: Snapshot, tried: AbstractSet[str], limit: int, sensitivities: Optional[Mapping[Tuple[str, str], float]] = None) -> Tuple[Candidate, ...]`; `propose_buffering(snapshot: Snapshot, tried: AbstractSet[str], limit: int) -> Tuple[Candidate, ...]`; Task 7 adds `propose_pin_swaps(snapshot: Snapshot, tried: AbstractSet[str], limit: int) -> Tuple[Candidate, ...]`. Algorithms receive accepted observations only and do no I/O.
- `optimize(config: Config) -> dict` in `optimizer.py` runs the loop and returns a labeled final result. Small trial-result dictionaries stay inside the optimizer/logging boundary; do not add a generic SearchContext/history/backend model.
- Initial bounded detail: at most `256` setup and `256` hold endpoint paths per scenario, at most `64` proposals per round, batch size `1`. Refresh observations after every acceptance; global metrics remain complete. Collect attempted move signatures per accepted version, persisting across equivalent restores so a restart does not cause an infinite retry loop.

### Production measurement and output policy

The former dual P0/R0 production baseline and mandatory production routing pipeline are removed. B0 is the immutable full-scenario **placement-estimated** input measurement. After every ECO/legalization refresh RC estimates and compare against B0. At finalization clean-load the exact staged DEF/Verilog, rebuild the same MCMM/placement RC model, verify actual graph/placement and remeasure; label it placement. Official routed/SPEF/fresh-process/formal/certified results remain mandatory external phase/release evidence.

Keep current/best accepted checkpoint and one last changed clean-reload-validated checkpoint, not a pool of routed checkpoints. A locally accepted candidate is not a routed improvement claim. Failures select a previously validated changed artifact or return nonzero. Required outputs are published only after validation; do not overwrite them.

### Minimal harness CLI

`harness/regress.py` has the following direct commands, not a generic experiment framework:

```text
inspect   <contest_repo> <design> <new_out>
calibrate <contest_repo> <design> <new_out>
submit    <contest_repo> <design> <new_out> -- <tool_command...>
evaluate  <contest_repo> <design> <new_out> --def FILE --verilog FILE
matrix    <contest_repo> <new_out> --designs aes jpeg --profiles sizing buffering combined
```

`inspect` creates an explicit launcher-compatible dev environment, starts the client, saves observations/canonical outputs and checks them; it does not certify a changed contestant solution. `calibrate` and `evaluate` call official `eval.sh`; `submit` calls official `run_submission.py`, preserving the tool command separator and spaces. `matrix` records profile runs plus baseline calibration rows. Add `pin-swap` only when implemented.

`harness/score.py <contest_repo> <design> <evaluation_dir> <new_score_json>` invokes official scoring with packaged references and measured runtimes. Explicit `--allow-unverified --runtimes FILE` is available only for labeled numerical experiments. `metric_deltas(baseline_rows: Sequence[dict], candidate_rows: Sequence[dict]) -> dict` produces raw same-scenario deltas; there is no local official-score clone.

Dependency sequence: Tasks 1–3 establish real P0/P1, 4 improves P2 quality, 5–6 add P3, 7 implements staged P4 pin swapping, and 8 verifies distribution/release. Task 8 may run after Task 6 for the P3 release; rerun its archive/evaluation checks after Task 7 to release the P4 extension. Do not defer safety checks to Task 4. Implement in an isolated worktree after document approval; task commit instructions below are future actions.
